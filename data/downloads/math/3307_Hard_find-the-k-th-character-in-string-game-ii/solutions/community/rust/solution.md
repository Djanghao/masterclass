# Intuition
The problem involves determining the k-th character in a sequence generated by a series of operations. Each operation can either append a character to the end or keep the sequence the same. The challenge is to efficiently navigate through potentially large sequences without explicitly constructing them.

# Approach
*   Logarithmic Indexing: The key observation is that the size of the sequence doubles with each operation. By using the properties of binary representation, we can deduce which part of the sequence the k-th character belongs to.
*   Count Characters: As we traverse back through the operations, we maintain a count of how many times 'a' appears based on the operations that resulted in character appends.
*   Character Calculation: After determining the final count of appended characters, we convert this count to a character by using modulo arithmetic to wrap around the alphabet.

impl Solution {
    pub fn kth_character(k: i64, operations: Vec<i32>) -> char {
        let mut k = k;
        let mut i = ((k as f64).log(2.0).ceil() as usize) - 1;
        let mut count = 0;

        while k > 1 {
            if k > (1i64 << i) {
                if operations[i] == 1 {
                    count += 1;
                }
                k -= 1i64 << i;
            }
            i -= 1;
        }

        let result = (count % 26) as u8 + b'a';
        result as char
    }
}
