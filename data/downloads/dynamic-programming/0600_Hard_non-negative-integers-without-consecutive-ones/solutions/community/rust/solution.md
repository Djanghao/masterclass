# Intuition
If a brute force function is created that can verify if a number matches the criteria, then some sample data can be generated by listing all the valid numbers from `0b_1` to `0b_0100_0000`. With that, patterns could be found in how the number of non-consecutive-ones (NCO) integers varies as the range of the sample data grows.
``` python
        1            1
        2           10
        4          100
        5          101
        8         1000  -+
        9         1001   |- 3 new numbers
        10        1010  -+
        16       10000  -+
        17       10001   |
        18       10010   |- 5 new numbers
        20       10100   |
        21       10101  -+
        32      100000  -+
        33      100001   |
        34      100010   |
        36      100100   |- 8 new numbers
        37      100101   |
        40      101000   |
        41      101001   |
        42      101010  -+
        64     1000000
```
As the width of the binary representation increases by a bit, it's visible that the number of new NCO integers added to the collection increments following the Fibonacci sequence.


DP Subproblem:
- How to determine how many NCO integers exist given `b`, the number of bits.
    - `nco_population(b) = fib(b) + fib(b - 1)... + fib(1)`

DP Recursive Relationship(s):
- We can determine how many new NCO's get added to the overall population when the bit width of the range increases by one using:
    - `nco(b) = nco(b - 1) + nco(b - 2)`
- A feature of the Fibonnaci sequence is, 
    - `sum( fib(i), fib(i - 1), .., fib(1) ) = fib(i + 2) - 1`
- So we can get the total number of NCO's in a given range in a similar manner.
    - `sum( nco(b),.. nco(1) ) = nco(b + 2)`
    - `nco_population(b) = nco(b + 2)`


# Approach
The NCO populations for the necessary bit widths are generated. The total population is taken from `dp[msb + 2]`. This would be the total population given the number of bits the input number `n` provides.

This number is then adjusted to account for non-NCO patterns in the input number `n` which limit the full range of NCO values.

# Complexity
- Time complexity: $$O(log(n))$$ The number is processed bitwise where the bit positions are powers of 2. So the work to be done grows log2 with the size of `n`.
- Space complexity: $$O(1)$$ The DP array is static given the size of the inputs limited to 32 bits.

# Code
``` rust
impl Solution {
    pub fn find_integers(n: i32) -> i32 {
        let mut dp  = [1; 33];
        let     msb = ilog2(n) as usize;
        let mut nco;

        macro_rules! n { [$i:expr] => { ((n >> $i) & 1) } }

        for i in 2..=msb + 2 {
            dp[i] = dp[i - 1] + dp[i - 2]; // Fibonacci sequence.
        }
        // Total possible pop given msb+1 bits.
        nco = dp[msb + 2]; 

        // Reduce population to fit within the range of n.
        for i in (0..msb).rev() {
            if n![i] == 1 && n![i + 1] == 1 {
                break;
            }
            if n![i] == 0 && n![i + 1] == 0 {
                nco -= dp[i];
            }
        }
        nco
    }
}

fn ilog2(n: i32) -> i32 {
    31 - n.leading_zeros() as i32
}
```
